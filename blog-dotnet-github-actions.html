CI/CD for .NET Projects Using GitHub Actions and Self-Hosted Runners

Posted on June 9, 2025 by Brahim Salim

Automating the build, test, and deployment workflow for .NET applications is essential for any modern development team. In this article, I’ll share a generic approach to setting up a CI/CD pipeline using GitHub Actions along with self-hosted Windows runners, especially useful when working with on-premise resources like IIS or custom infrastructure.

💡 Why Use GitHub Actions?

GitHub Actions provides an integrated way to automate software workflows — directly from your GitHub repository. For .NET developers, it enables continuous integration and deployment (CI/CD) with:

  • Cross-platform runners (Linux, macOS, Windows)
  • Support for .NET SDK versions
  • Custom deployment logic using PowerShell or bash
  • Secure secrets management

🏗️ When to Use a Self-Hosted Runner

While GitHub-hosted runners work for most cases, there are scenarios where a self-hosted Windows runner is ideal:

  • Deploying to local IIS or intranet servers
  • Using licensed software like Visual Studio Test tools
  • Accessing internal resources or shared drives

🧱 Typical Pipeline Tasks

The pipeline typically performs the following:

  • Check out source code
  • Restore NuGet packages
  • Build the solution with MSBuild
  • Run unit or integration tests using vstest.console.exe
  • Optionally, deploy the output (e.g. to IIS)

⚙️ Sample GitHub Actions Workflow

Here’s a simplified version of a workflow using a Windows self-hosted runner:

name: .NET CI/CD

on:
  push:
    branches: [ main ]

jobs:
  build-test:
    runs-on: self-hosted  # Assumes a Windows runner

    steps:
    - name: Checkout Code
      uses: actions/checkout@v2

    - name: Setup MSBuild
      uses: microsoft/setup-msbuild@v1

    - uses: nuget/setup-nuget@v1

    - name: Restore Dependencies
      run: nuget restore MySolution.sln

    - name: Build Solution
      run: msbuild.exe MyProject/MyProject.csproj /p:Configuration=Release

    - name: Run Tests
      run: |
        & "C:\Program Files (x86)\Microsoft Visual Studio\2019\TestAgent\Common7\IDE\Extensions\TestPlatform\vstest.console.exe" MyTests\bin\Release\MyTests.dll

🔐 Secrets and Security

GitHub Secrets can be used to securely pass tokens, credentials, or configuration values. For example: 

env:
  DEPLOY_PASSWORD: ${{ secrets.DEPLOY_PASSWORD }}

🛠️ Optional PowerShell for Deployment

A custom PowerShell script can be used in the pipeline to:

  • Stop IIS
  • Back up the current deployment
  • Copy new build artifacts
  • Restart services
iisreset /stop
# Backup logic here
Copy-Item -Path ".\output" -Destination "C:\inetpub\wwwroot\myapp" -Recurse -Force
iisreset /start

✅ Conclusion

GitHub Actions combined with self-hosted Windows runners is a powerful option for .NET teams working in hybrid environments. Whether you're building cloud apps or managing on-premise infrastructure, this approach gives you full control, flexibility, and consistency.

This setup is easy to evolve — you can integrate notifications, parallel jobs, deployment gates, or even Docker containers as needed.
