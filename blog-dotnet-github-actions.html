🚀 Setting Up CI/CD for .NET Web Applications Using GitHub Actions and Self-Hosted Windows Runners

Posted on June 9, 2025 by Brahim Salim

Modern development workflows require automation, consistency, and flexibility — especially when deploying .NET web applications to on-premises infrastructure. This guide outlines a step-by-step approach to building a CI/CD pipeline using GitHub Actions with a self-hosted Windows runner, perfect for teams deploying to IIS or other internal environments.

🧩 Overview

This guide covers:

  • Installing the necessary environment using Chocolatey
  • Setting up a self-hosted GitHub Actions runner
  • Installing build tools
  • Deploying a web app to IIS via a GitHub Actions pipeline

📦 Step 1: Install Chocolatey on the Server

Chocolatey simplifies package management on Windows.

  1. Connect to the server where the application will be hosted (It can be your local machine).
  2. Open PowerShell as Administrator.
  3. Run the following command to install Chocolatey:
Set-ExecutionPolicy Bypass -Scope Process -Force;
[System.Net.ServicePointManager]::SecurityProtocol = [System.Net.ServicePointManager]::SecurityProtocol -bor 3072;
iex ((New-Object System.Net.WebClient).DownloadString('https://community.chocolatey.org/install.ps1'))

Verify installation:

choco -v

🛠️ Step 2: Install Required Build Tools

Use Chocolatey to install Visual Studio build tools ( here the version of the build tools depends on the version of .NET project ):

choco install visualstudio2017buildtools `
--params "'--add Microsoft.VisualStudio.Workload.WebBuildTools --quiet --norestart'" -y

You can find the packages of chocolatey here : https://community.chocolatey.org/packages/

⚙️ Step 3: Set Up a GitHub Self-Hosted Runner

  1. Go to your GitHub repository.
  2. Navigate to: Settings > Actions > Runners
  3. Click "New self-hosted runner" and follow the instructions:
    • Select your operating system and architecture
    • Run the provided shell commands on your server
    • (Optional) Install as a Windows service for persistence

💡 Tip: Use C:\actions-runner as the runner directory to simplify permission management.

Once completed, you should see:

√ Connected to GitHub
Listening for Jobs...

🌐 Step 4: Configure IIS for Hosting the Application

  1. Open IIS Manager (inetmgr).
  2. Add a new website with:
    • Site Name: your-site-name
    • Physical Path: C:\inetpub\wwwroot\YourApp
    • Port: 80 (or another of your choosing)
  3. Ensure the deployment user has write access to the website folder.

🤖 Sample GitHub Actions Workflow (Windows Runner)

The following is a complete GitHub Actions workflow that covers the full build and deployment lifecycle including backing up the current IIS deployment to prevent downtime or data loss:

Pipeline Breakdown

  • Trigger: On every push to the main branch
  • Environment: A self-hosted Windows runner configured with necessary tools
  • Steps:
    • Checkout source code
    • Set up MSBuild and NuGet
    • Restore NuGet packages
    • Backup the existing IIS deployment (timestamped)
    • Stop IIS, move old deployment to backup, create a fresh deployment folder
    • Build and publish the new application
    • Restart IIS after deployment
name: .NET CI/CD

on:
  push:
    branches: [ main ]

jobs:
  build-deploy:
  runs-on: self-hosted // label of self hosted runner

  steps:
    - name: Checkout Code
      uses: actions/checkout@v2

    - name: Setup MSBuild
      uses: microsoft/setup-msbuild@v1

    - uses: nuget/setup-nuget@v1

    - name: Restore NuGet Packages
      run: nuget restore MyApp.sln

    - name: Backup Old Deployment
      shell: powershell
      run: |
        $DeployPath = "C:\inetpub\wwwroot\MyApp"
        $BackupPath = "C:\inetpub\wwwroot\Backups"
        $Timestamp = Get-Date -Format "yyyyMMdd_HHmmss"
        $BackupFolder = "$BackupPath\MyApp_$Timestamp"

        if (!(Test-Path $BackupPath)) {
            New-Item -ItemType Directory -Path $BackupPath | Out-Null
        }

        Write-Host "Stopping IIS..."
        iisreset /stop

        if (Test-Path $DeployPath) {
            Move-Item -Path $DeployPath -Destination $BackupFolder
            Write-Host "Backup completed: $BackupFolder"
        }

        New-Item -ItemType Directory -Path $DeployPath | Out-Null

        Write-Host "Starting IIS..."
        iisreset /start

    - name: Build and Publish Projects
      run: |
        msbuild.exe MyApp/MyApp.csproj /p:DeployOnBuild=true /p:PublishProfile=NameProfile /p:Configuration=Release

    - name: Final IIS Restart
      run: iisreset

🔐 Managing Secrets Securely

Use GitHub’s Secrets to manage sensitive variables like passwords or tokens:

env:
  DEPLOY_PASSWORD: ${{ secrets.DEPLOY_PASSWORD }}

✅ Conclusion

Using GitHub Actions with a self-hosted Windows runner provides a powerful, flexible pipeline for deploying .NET apps in environments where cloud runners don’t fit — like internal servers.

This setup gives you:

  • Full control of the environment
  • Seamless integration with GitHub
  • Automation across build, test, and deployment stages
